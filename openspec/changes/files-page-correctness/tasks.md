# Tasks

Every task states its verification. Phases are ordered by real dependency, which is derived from **file ownership**, not from the proposal's recommended outline.

**Parallelisation rules applied.** Two tasks may run concurrently only if they write disjoint file sets. Derived constraints:

- `package.json`, `.gitignore` — Phase 0 only. Single writer.
- `src/controllers/fs.controller.js`, `src/routes/fs.routes.js` — Phase 1 only. Single writer (`fs.controller.js` is a degree-84 conflict hotspot; see `design.md` R3).
- `src/utils/fileTypes.js` — Phase 1 only, and only the extension map. Single writer.
- `public/assets/js/files.js` — Phases 0, 2, 3, 4, 5. **Strictly sequential.** Highest-degree file in the change.
- `public/files.html` — Phases 2, 4, 5. Sequential with each other.
- `public/assets/css/files.css` — Phase 5 only. Single writer.
- `public/index.html`, `uploads.html`, `settings.html` — Phase 2 only (sidebar entries). Disjoint from `files.html`, so parallelisable with each other.
- `server.js` — Phase 0 only. **Do not reorder any mount** (`design.md` R4).
- `test/**` — every phase adds to it. Parallelisable with any phase's source work provided the test files differ.

**Deviation from the proposal's outline, stated explicitly.** The proposal orders "stop the bleeding" first but places the test-command scoping in the guardrails phase. It belongs in Phase 0 instead: task 0.1 is what makes every subsequent phase's verification trustworthy, and it is the fix for a currently-red suite.

**Contract freeze.** Phase 2 may not begin until the Phase 1 contract gate is green against a live server. `public/assets/js/api.js` is never modified, so any contract surprise found in Phase 2 is a defect found late, not a negotiation.

**Approval gates.** Tasks marked **[A1]**–**[A6]** must not begin without the corresponding human approval recorded in `design.md`.

**Concurrent-change gate.** `openspec/changes/upload-pipeline-correctness` (Uploads page) lists `src/controllers/fs.controller.js` and `src/routes/fs.routes.js` as untouched and owned by **this** change, while independently reproducing three of the same server-side upload defects (field ordering, ignored overwrite flag, absent size limit). Phase 1 is therefore the sole owner of both files, and its tasks 1.1, 1.2, 1.7, 1.8 and 1.9 satisfy that change's server-side expectations. **Do not begin Phase 1 until the ownership split is confirmed** — see `design.md` R12. That change owns `errorHandler.js` and `config/env.js` for its stack-trace-disclosure defect, which this change neither claims nor covers.
